# Контекст проекта Stilltime

Этот файл относится ко всему репозиторию. Читай его перед изменениями и обновляй при согласованных изменениях поведения или рабочего процесса. Актуальные указания пользователя имеют приоритет над описанными здесь предпочтениями.

## Цель и общение

- Stilltime — демонстрационный проект для резюме: таймер на Avalonia UI для Windows и Android.
- Общаться с пользователем на русском. Весь интерфейс приложения — на английском.
- Пользователь предпочитает пошаговую работу: для задачи из нескольких этапов предложить план и спрашивать разрешение на следующий этап. Каждый законченный этап коммитить отдельно. Прямое поручение на небольшую правку разрешает выполнить эту правку.
- В конце сообщать результат, выполненные проверки и коммит. Не выдавать локальный коммит за отправленный в GitHub.
- Перед работой проверять git status. Сохранять пользовательские изменения; добавлять в коммит только относящиеся к задаче файлы. Не использовать git add . без проверки состава.
- В рабочем каталоге встречаются документы резюме, Python-скрипты и изображения проверки. Они не относятся к таймеру автоматически: не удалять и не коммитить их без поручения.
- Репозиторий: https://github.com/HannaPavlenko/Timer.git. Текущий рабочий процесс использует main и отдельные коммиты с отправкой в origin/main. Перед отправкой проверять текущую ветку и remote, не делать force push.

## Архитектура

- .NET 10; Android — net10.0-android, минимум API 23. Нужны Android workload и Android SDK.
- Версии пакетов централизованы в Directory.Packages.props. Версии пакетов Avalonia должны быть согласованы; сверять фактические версии в этом файле.
- Timer.Core/TimerEngine.cs — движок отсчёта с монотонным временем и TimeProvider. Частота обновления UI не должна определять точность времени.
- Timer.Core/TimerSnapshot.cs — снимок состояния. Для истории интервалов использовать TotalElapsed, а не время отдельной фазы.
- Timer.Core/TimerHistoryEntry.cs — запись истории; TimerHistorySession.cs — переходы её состояний; TimerHistoryStore.cs — JSON-хранилище с ограничением размера.
- Timer/ViewModels/MainViewModel.cs — команды, настройки режимов, движок, обновление UI и история. Конструктор с ITimerHistoryStore позволяет тестировать без пользовательского AppData.
- Timer/ViewModels/TimerHistoryItemViewModel.cs — отображение одной записи и команды Restart, Stop, Delete.
- Timer/Views/MainView.axaml — общий экран, вкладки режимов и карточки истории. Это один общий экран с переключаемым содержимым, а не четыре независимых XAML-страницы.
- Timer/Controls/DigitsOnlyTextBox.cs — ввод цифр, включая фильтрацию вставленного текста. StyleKeyOverride сохраняет оформление TextBox.
- Timer.Desktop/ и Timer.Android/ — платформенные точки входа. Общую логику держать в Timer.Core/ и Timer/.
- Timer.Core.Tests/ — движок, хранение и состояния истории; Timer.App.Tests/ — команды и поведение модели экрана.
- tools/Timer.Preview — снимки настоящей Avalonia-разметки через headless Skia с отдельным демонстрационным хранилищем.

## Требования к таймерам

- Режимы: Stopwatch, Count up, Countdown, Intervals. Они представлены отдельными вкладками.
- Одновременно работает один таймер. Запуск другой записи завершает предыдущий отсчёт и сохраняет его результат.
- Stopwatch считает вверх без цели. Count up считает до цели. Countdown считает от цели до нуля.
- Target time у Count up и Countdown независимы: изменение одного режима не меняет настройки другого.
- Intervals: подготовка один раз перед работой, затем работа и отдых по раундам; после последнего рабочего интервала отдыха нет.
- Prepare по умолчанию 0:00; нулевая подготовка пропускается.
- Время отображается без десятых долей секунды. Для обратного отсчёта оставшиеся неполные секунды округляются вверх.
- Поля времени принимают только ASCII-цифры. Пустое поле минут или секунд трактуется как 0: например, пустые минуты и 6 секунд — допустимая длительность.
- Диапазоны: минуты 0–999, секунды 0–59, раунды 1–99. Целевая длительность, работа и отдых положительны; подготовка может быть нулевой.
- Основная кнопка поддерживает Start / Pause / Resume. Resume продолжает тот же запуск; это отличается от Restart в истории.

## История: важные договорённости

- Каждая вкладка показывает только записи своего режима.
- Новый Start через основные элементы управления создаёт новую запись с новым ID. Записи отображаются в порядке добавления, новые добавляются в конец.
- Restart в истории запускает отсчёт с нуля в той же записи: ID и позиция сохраняются, прошедшее время обнуляется, дата и время запуска обновляются. Новую строку создавать нельзя.
- В той же строке Restart заменяется на Stop во время работы, а после Stop снова становится Restart. Это основной ожидаемый пользователем сценарий.
- Restart доступен у Paused и Stopped с допустимыми сохранёнными настройками. Completed сейчас отображается как статус; не расширять это поведение без задачи.
- Stop относится только к текущему ID: устаревшая команда другой записи не должна останавливать новый таймер. Stop сохраняет результат и возвращает основной таймер в Ready.
- Время текущей записи обновляется на экране во время отсчёта. Не писать JSON на каждом тике UI: сохранение выполняется при переходах состояния.
- Delete удаляет конкретную запись. Удаление работающей записи не останавливает основной таймер, но запись не должна появиться снова при паузе или остановке.
- Лимит — 10 записей суммарно по всем режимам. FIFO определяется порядком добавления, а не обновлённым временем Restart. Одиннадцатая запись вытесняет первую; обновление и Restart не занимают новый слот.
- При загрузке старого файла с более чем 10 записями сохраняются последние 10.
- Файл: Environment.SpecialFolder.LocalApplicationData / Stilltime / history.json. На Windows обычно это %LOCALAPPDATA%\Stilltime\history.json. Не использовать пользовательский файл для тестовых данных.
- Сохранение идёт через временный файл и замену целевого. Повреждённый JSON не перезаписывается молча: хранилище сообщает InvalidDataException.
- История переживает перезапуск приложения, активный отсчёт автоматически не восстанавливается. Запись прошлого процесса со статусом Running становится Stopped; её время ограничено последним сохранённым состоянием.

## Интерфейс

- Нейтральные тёплые цвета: фон #F3EFE8, карточки #FFFCF7 / #F8F3EB, акцент #B96B50, текст #292D28.
- Не возвращать удалённые рекламные и мотивационные надписи, нумерованные подзаголовки и синюю линию выбранной вкладки.
- Пользователь убрал видимую плашку ошибки длительности; валидацию сохранять, плашку самостоятельно не возвращать.
- Карточка истории: название режима сверху; ниже одна строка с длительностью, датой запуска, временем запуска, кнопкой действия и Delete.
- Пример строки: 00:04 · Nov 5, 2026 · 17:19. Слово Elapsed в истории не показывать.
- Сохранять компактную строку на узких экранах. Проверять ширины 320–360 px; длинные длительности и статусы могут потребовать отдельной проверки обрезки текста.

## Проверки и инструменты

```powershell
dotnet restore Timer.sln
dotnet test Timer.Core.Tests/Timer.Core.Tests.csproj --no-restore
dotnet test Timer.App.Tests/Timer.App.Tests.csproj --no-restore
dotnet build Timer.Desktop/Timer.Desktop.csproj --no-restore
dotnet build Timer.Android/Timer.Android.csproj --no-restore
dotnet run --project Timer.Desktop
dotnet run --project tools/Timer.Preview -- history 320 artifacts/history-preview.png
dotnet run --project tools/Timer.Preview -- stopwatch 520 artifacts/desktop-preview.png
dotnet run --project tools/Timer.Preview -- intervals 360 artifacts/intervals-preview.png
dotnet run --project tools/Timer.Preview -- verify-input
git diff --check
```

- Использовать --no-restore только при наличии восстановленных зависимостей. Проверки выбирать по изменению; не пересобирать Android ради каждой текстовой правки.
- Для логики истории важны проверки ID и количества записей, переходов Restart → Stop → Restart, остановки предыдущего запуска, фильтрации режимов и FIFO.
- Скриншот headless проверяет разметку, но не заменяет запуск на реальном Android-устройстве. После генерации просматривать изображение, а не только проверять наличие файла.
- Артефакты локальных проверок складывать в игнорируемый artifacts/. Не коммитить bin/, obj/, локальную историю и временные изображения.
- Запущенные Timer.Desktop и Visual Studio могут удерживать DLL. Не закрывать пользовательское приложение без необходимости; использовать отдельную папку вывода, например -p:BaseOutputPath=D:/Work/Timer/artifacts/check-build/.
- В песочнице сборка Avalonia может падать из-за доступа к %LOCALAPPDATA%\AvaloniaUI\BuildServices\buildtasks.log. При таком отказе использовать предусмотренный запрос разрешения на сборку вне песочницы; это ограничение окружения, а не ошибка кода.
- NU1900 о недоступности nuget.org означает, что не получены данные аудита пакетов. Сообщать фактический результат сборки и существенные ограничения, не называть предупреждение успешным аудитом.
