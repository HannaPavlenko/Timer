# Контекст проекта Stilltime

Этот файл относится ко всему репозиторию. Читай его перед изменениями и обновляй при согласованных изменениях поведения или рабочего процесса. Актуальные указания пользователя имеют приоритет над описанными здесь предпочтениями.

## Codex models and delegation

- Use GPT-6.1 Sol (`gpt-6.1-sol`, medium) as the main model for implementation, debugging, routine
  verification, and integration. Keep small or tightly coupled tasks with the main agent.
- Delegate independent, narrowly scoped repository research to GPT-6 Luna (`gpt-6-luna`, low) when
  it saves work. Examples include tracing callers, locating relevant tests, and mapping API or
  database entry points. Give each subagent a specific question and the minimum relevant context.
- Delegate user-requested code reviews to GPT-6 Astra (`gpt-6-astra`, medium) by default. During
  implementation, use Astra for independent review of high-risk changes such as migrations that
  rewrite existing data, or for an architectural decision Sol cannot resolve from the evidence.
  Use high reasoning effort when the review involves subtle cross-layer invariants or data-loss risk.
- The main agent verifies subagent findings against the code, runs relevant checks, and reports the
  result. If a requested reviewer model is unavailable, say so before using a fallback and name the
  model that actually performed the review.

## Цель и общение

- Stilltime — демонстрационный проект для резюме: таймер на Avalonia UI для Windows, Android и браузера.
- Общаться с пользователем на русском. Весь интерфейс приложения — на английском.
- Пользователь предпочитает пошаговую работу: для задачи из нескольких этапов предложить план и спрашивать разрешение на следующий этап. Каждый законченный этап коммитить отдельно. Прямое поручение на небольшую правку разрешает выполнить эту правку.
- В конце сообщать результат, выполненные проверки и коммит. Не выдавать локальный коммит за отправленный в GitHub.
- Перед работой проверять git status. Сохранять пользовательские изменения; добавлять в коммит только относящиеся к задаче файлы. Не использовать git add . без проверки состава.
- В рабочем каталоге встречаются документы резюме, Python-скрипты и изображения проверки. Они не относятся к таймеру автоматически: не удалять и не коммитить их без поручения.
- Репозиторий: https://github.com/HannaPavlenko/Timer.git. Текущий рабочий процесс использует main и отдельные коммиты с отправкой в origin/main. Перед отправкой проверять текущую ветку и remote, не делать force push.

## Архитектура

- Перед написанием, изменением или ревью кода C#, включая тесты, прочитай [правила оформления C#](csharp-style.md) и применяй их к затронутому коду.
- .NET 10; Android — net10.0-android, минимум API 23. Нужны Android workload и Android SDK.
- Версии пакетов централизованы в Directory.Packages.props. Версии пакетов Avalonia должны быть согласованы; сверять фактические версии в этом файле.
- Timer.Core/TimerEngine.cs — движок отсчёта с монотонным временем и TimeProvider. Частота обновления UI не должна определять точность времени.
- Timer.Core/TimerSnapshot.cs — снимок состояния. Для истории интервалов использовать TotalElapsed, а не время отдельной фазы.
- Timer.Core/TimerHistoryEntry.cs — запись истории; TimerHistorySession.cs — переходы её состояний; TimerHistoryStore.cs — JSON-хранилище с ограничением размера.
- Свойства ViewModel объявлять явно с get/set и SetProperty, без [ObservableProperty]. Сохранять уведомления зависимых свойств и обновление предварительного просмотра в сеттерах.
- Timer/ViewModels/MainViewModel.cs — команды, настройки режимов, движок, обновление UI и история. Конструктор с ITimerHistoryStore позволяет тестировать без пользовательского AppData.
- Timer/ViewModels/TimerHistoryItemViewModel.cs — отображение одной записи и команды Restart, Stop, Delete.
- Timer/Views/MainView.axaml — общий экран, вкладки режимов и карточки истории. Это один общий экран с переключаемым содержимым, а не четыре независимых XAML-страницы.
- Timer/Controls/DigitsOnlyTextBox.cs — ввод цифр, включая фильтрацию вставленного текста. StyleKeyOverride сохраняет оформление TextBox.
- Timer.Desktop/ и Timer.Android/ — платформенные точки входа. Общую логику держать в Timer.Core/ и Timer/.
- Timer.Browser/ — точка входа Avalonia WebAssembly на net10.0-browser. Она использует общий MainView, сохраняет JSON истории и настроек звука через localStorage и воспроизводит общие WAV-сигналы через Web Audio. iOS может приостанавливать веб-приложение в фоне, поэтому звуковые сигналы при блокировке экрана не гарантируются.
- На Android каждая Activity получает новый MainView с общей для процесса MainViewModel. При пересоздании экрана активный отсчёт продолжается с прежним ID записи и учитывает время между экранами.
- На Windows Program.Main вызывает SingleInstanceApplication до инициализации Avalonia, звука и истории. Именованный mutex с SID пользователя удерживается синхронно на главном потоке на всё время работы окна; область — все сеансы одного пользователя. Второй процесс сразу завершается без чтения истории. После аварийного завершения владельца AbandonedMutexException означает успешное получение mutex новым процессом. Android не использует это ограничение.
- tools/Timer.Desktop.TestHost — консольный вспомогательный процесс для проверок single-instance в Timer.App.Tests. Использовать уникальные тестовые имена mutex и отдельные файлы истории; не брать блокировку работающего пользовательского Stilltime в тестах.
- Timer.Core.Tests/ — движок, хранение и состояния истории; Timer.App.Tests/ — команды и поведение модели экрана.
- tools/Timer.Preview — снимки настоящей Avalonia-разметки через headless Skia с отдельным демонстрационным хранилищем.

## Требования к таймерам

- Режимы: Stopwatch, Count up, Countdown, Intervals. Они представлены отдельными вкладками.
- Одновременно работает один таймер. Запуск другой записи завершает предыдущий отсчёт и сохраняет его результат.
- Stopwatch считает вверх без цели. Count up считает до цели. Countdown считает от цели до нуля.
- Target time у Count up и Countdown независимы: изменение одного режима не меняет настройки другого.
- Intervals: каждый раунд включает Prepare, Work и Rest, в том числе последний. При одном раунде Rest тоже отсчитывается.
- Prepare по умолчанию 0:00; нулевая подготовка пропускается. Rounds по умолчанию 1, чтобы ввод положительных Work и Rest позволял запустить Intervals.
- Время отображается без десятых долей секунды. Для обратного отсчёта оставшиеся неполные секунды округляются вверх.
- Поля времени принимают только ASCII-цифры. Пустое поле минут или секунд трактуется как 0: например, пустые минуты и 6 секунд — допустимая длительность.
- Диапазоны: минуты 0–999, секунды 0–59, раунды 1–99. Целевая длительность, работа и отдых положительны; подготовка может быть нулевой.
- После автоматического завершения Intervals (включая запуск через Restart) поля Prepare, Work, Rest и Rounds сохраняют заданные значения. Reset очищает настройки; FINISHED и запись истории сохраняются после завершения.
- Reset в Intervals обнуляет все поля Prepare, Work и Rest, возвращает Rounds к 1 и основной таймер к 00:00; история сохраняется.
- После FINISHED кнопка Start запускает новый отсчёт. Если поля Count up или Countdown обнулены при завершении, Start восстанавливает прежнюю цель. Введённая новая допустимая цель имеет приоритет.
- Фокус на обнулённых полях Target time после FINISHED сохраняет статус и результат: пустая строка при редактировании эквивалентна нулю. Ввод новой допустимой цели обновляет предварительный просмотр.
- В Countdown при нулевой цели в состоянии Ready полоса прогресса скрыта как при открытии вкладки, так и после Stop в истории.
- Основная кнопка поддерживает Start / Pause / Resume. Resume продолжает тот же запуск; это отличается от Restart в истории.

## Звук

- Галочка Sound отображается в Count up, Countdown и Intervals. На вкладке Stopwatch она скрыта, но место под неё и индикатор прогресса сохраняется, чтобы кнопки были на той же высоте.

- Общая галочка Sound, по умолчанию выключена. Выбор сохраняется в LocalApplicationData / Stilltime / sound.json через SoundSettingsStore.
- При включённом Sound начало Prepare — один сигнал, Work — два, Rest — три. После последнего Rest звучит синтезированный гонг. При Prepare = 0 сразу звучат два сигнала Work. Start и Restart интервалов озвучивают начальную фазу; Pause/Resume не повторяют её сигнал.
- Count up/Countdown издают один сигнал завершения. Reset, Stop и переключение режима беззвучны. Включение Sound не воспроизводит пропущенные сигналы; после пропущенных обновлений звучит только текущая фаза.
- MainViewModel.SoundRequested передаёт TimerSoundEventArgs. TimerSoundAudio создаёт общий PCM WAV для обеих платформ. WindowsSound использует PlaySound в фоновой задаче; AndroidSound — MediaPlayer с временным WAV в кэше и освобождением ресурсов. Громкость зависит от устройства.
- AndroidSound явно вызывает MediaPlayer.Release() в finally до Dispose и удаления временного WAV, включая ошибку подготовки/воспроизведения и тайм-аут. Одного using/Dispose недостаточно для своевременного освобождения нативного плеера.
- SoundPlayback подавляет перекрывающиеся сигналы и перехватывает ошибки аудио. App подписывает созданные MainViewModel на воспроизведение.
- Не собирать Android и desktop/tests параллельно: проекты используют общие obj и могут блокировать Timer.dll/Timer.pdb.

## История: важные договорённости

- Каждая вкладка показывает только записи своего режима.
- Название записи (Name) сохраняется автоматически при вводе и остаётся после Restart, Stop и перезапуска приложения. Переименование не меняет дату запуска или порядок FIFO; старые записи без Name поддерживаются.
- Новый Start через основные элементы управления создаёт новую запись с новым ID. На всех вкладках записи отображаются по StartedAtUtc от самых недавних к более старым; сортировка UI не меняет очередь FIFO в хранилище.
- Restart в истории запускает отсчёт с нуля в той же записи: ID сохраняется, прошедшее время обнуляется, дата и время запуска обновляются. Запись перемещается в списке согласно новому времени запуска; дубликат создавать нельзя.
- В Count up и Countdown при запуске, Restart и паузе поля Target time показывают заданную длительность без серого фона (IsReadOnly вместо IsEnabled). Оба поля обнуляются после Stop или автоматического завершения; FINISHED и результат отсчёта сохраняются.
- В той же строке Restart заменяется на Stop во время работы, а после Stop снова становится Restart. Это основной ожидаемый пользователем сценарий.
- Restart доступен у Paused и Stopped с допустимыми сохранёнными настройками, а также у Completed в режимах Count up, Countdown и Intervals.
- Stop относится только к текущему ID: устаревшая команда другой записи не должна останавливать новый таймер. Stop сохраняет результат и возвращает основной таймер в Ready. В Count up и Countdown кнопка Stop также обнуляет Minutes и Seconds в Target time; сохранённая цель записи остаётся прежней для Restart.
- В истории Count up и Countdown в строке длительности показывается сохранённая цель Target вместо фактически отсчитанного времени; отдельной строки Target нет. В Stopwatch и Intervals время текущей записи обновляется на экране во время отсчёта. Не писать JSON на каждом тике UI: сохранение выполняется при переходах состояния.
- Delete удаляет конкретную запись. Удаление работающей записи не останавливает основной таймер, но запись не должна появиться снова при паузе или остановке.
- Лимит — 10 записей суммарно по всем режимам. FIFO определяется порядком добавления, а не обновлённым временем Restart. Одиннадцатая запись вытесняет первую; обновление и Restart не занимают новый слот.
- При загрузке старого файла с более чем 10 записями сохраняются последние 10.
- Файл: Environment.SpecialFolder.LocalApplicationData / Stilltime / history.json. На Windows обычно это %LOCALAPPDATA%\Stilltime\history.json. Не использовать пользовательский файл для тестовых данных.
- Сохранение идёт через временный файл и замену целевого. Повреждённый JSON не перезаписывается молча: хранилище сообщает InvalidDataException.
- При первом запуске без каталога Stilltime хранилища создают каталог и используют значения по умолчанию. Если путь каталога занят файлом, предупреждение для истории и звука появляется сразу при загрузке.
- В каждой записи history.json обязательны Id, Mode, StartedAtUtc, Status и Elapsed. Отсутствие любого из них вызывает предупреждение о хранении и переход на историю в памяти без перезаписи файла.
- Перед обрезкой истории проверяются null-записи, пустые и повторяющиеся ID, неизвестные режимы/статусы и отрицательные значения времени/раундов. Старые записи без Name и без настроек поддерживаются.
- На уровне UI SessionHistoryStore и SessionSoundSettingsStore перехватывают InvalidDataException, IOException и UnauthorizedAccessException. После первого сбоя соответствующее хранилище работает только в памяти до закрытия приложения; повторных обращений к файлу нет, второе хранилище работает независимо. Английское сообщение StorageErrorMessage объясняет потерю временных изменений после закрытия и восстановление по README; это отдельное сообщение, не плашка валидации длительности.
- TimerHistorySession изменяет текущую запись после успешной операции хранилища, чтобы прямой вызов с ошибкой позволял повторить Update, Stop или Delete.
- При штатном закрытии настольного окна работающий таймер сохраняет фактическое прошедшее время в запись с прежним ID. Снимок берётся в момент Closed, в том числе между обновлениями интерфейса.
- История переживает перезапуск приложения, активный отсчёт автоматически не восстанавливается. Запись прошлого процесса со статусом Running становится Stopped; её время ограничено последним сохранённым состоянием.

## Интерфейс

- Блок отображения времени занимает треть высоты MainView и изменяет высоту при изменении окна. Viewbox масштабирует фактическую строку времени по доступной ширине и высоте; при появлении часов цифры могут стать меньше.
- Под цифрами сохраняется место для строки деталей даже на Stopwatch, чтобы цифры располагались на одинаковой высоте на всех вкладках.
- Нейтральные тёплые цвета: фон #F3EFE8, карточки #FFFCF7 / #F8F3EB, акцент #B96B50, текст #292D28.
- Над цифрами таймера не показывать PhaseLabel (SET YOUR TIME, TIME REMAINING, WORK INTERVAL и другие подписи) на всех вкладках.
- Не возвращать удалённые рекламные и мотивационные надписи, нумерованные подзаголовки и синюю линию выбранной вкладки.
- Пользователь убрал видимую плашку ошибки длительности; валидацию сохранять, плашку самостоятельно не возвращать.
- В настройках истории Intervals количество раундов (`1 round` или `N rounds`) всегда показывать отдельной строкой под Prepare, Work и Rest. Число и слово разделять неразрывным пробелом.
- Карточка истории: редактируемое название таймера сверху (до 80 символов, пустое поле показывает название режима); ниже одна строка с длительностью, кнопкой действия и Delete.
- Основная кнопка показывает треугольник для Start/Resume и значок паузы во время работы; Reset — две круговые стрелки. Сохранять английские подсказки и имена для доступности.
- В истории Restart отображается значком круглой стрелки, Delete — корзиной. Stop отображается значком квадрата. У всех кнопок английские подсказки и имена для доступности.
- Пример длительности: 00:04. Дату, время запуска и слово Elapsed в истории не показывать. StartedAtUtc сохраняется для сортировки.
- Сохранять компактную строку на узких экранах. Проверять ширины 320–360 px; длинные длительности и статусы могут потребовать отдельной проверки обрезки текста.
- Вкладкам Stopwatch и Countdown выделено больше ширины, чтобы полные названия помещались при 320 px без уменьшения шрифта. Сохранять видимость всех четырёх вкладок.
- На Android все девять полей времени и Rounds связаны со своими видимыми подписями через AutomationProperties.LabeledBy. У Work и Rest различаются подписи минут и секунд даже при одинаковых значениях.
- У полей времени и Rounds заданы английские AutomationProperties.Name с назначением/единицами и HelpText с допустимым диапазоном; сохранять их при изменении разметки.

## Проверки и инструменты

- При отправке тега версии вида `v1.0.0` workflow `Publish Windows release` собирает автономный ZIP для Windows x64, запускает приложение из распакованного архива и публикует ZIP в GitHub Releases.

- При push и pull request GitHub Actions запускает две задачи на отдельных машинах: `windows` собирает desktop и запускает оба тестовых проекта в Release, `android` восстанавливает workload и собирает Android-проект в Debug.
- Workflow `Publish Stilltime web app` публикует содержимое `Timer.Browser/bin/Release/net10.0-browser/publish/wwwroot` на GitHub Pages. Источник Pages — GitHub Actions. Все ресурсы веб-оболочки должны работать по относительным путям, так как сайт открывается в каталоге репозитория `/Timer/`.

```powershell
dotnet restore Timer.sln
dotnet test Timer.Core.Tests/Timer.Core.Tests.csproj --no-restore
dotnet test Timer.App.Tests/Timer.App.Tests.csproj --no-restore
dotnet build Timer.Desktop/Timer.Desktop.csproj --no-restore
dotnet build Timer.Android/Timer.Android.csproj --no-restore
dotnet run --project Timer.Desktop
dotnet run --project tools/Timer.Preview -- history 320 artifacts/history-preview.png
dotnet run --project tools/Timer.Preview -- stopwatch 520 artifacts/desktop-preview.png
dotnet run --project tools/Timer.Preview -- intervals 360 artifacts/intervals-preview.png
dotnet run --project tools/Timer.Preview -- verify-input
git diff --check
```

- Использовать --no-restore только при наличии восстановленных зависимостей. Проверки выбирать по изменению; не пересобирать Android ради каждой текстовой правки.
- Для логики истории важны проверки ID и количества записей, переходов Restart → Stop → Restart, остановки предыдущего запуска, фильтрации режимов и FIFO.
- Скриншот headless проверяет разметку, но не заменяет запуск на реальном Android-устройстве. После генерации просматривать изображение, а не только проверять наличие файла.
- Артефакты локальных проверок складывать в игнорируемый artifacts/. Не коммитить bin/, obj/, локальную историю и временные изображения.
- Запущенные Timer.Desktop и Visual Studio могут удерживать DLL. Не закрывать пользовательское приложение без необходимости; использовать отдельную папку вывода, например -p:BaseOutputPath=D:/Work/Timer/artifacts/check-build/.
- В песочнице сборка Avalonia может падать из-за доступа к %LOCALAPPDATA%\AvaloniaUI\BuildServices\buildtasks.log. При таком отказе использовать предусмотренный запрос разрешения на сборку вне песочницы; это ограничение окружения, а не ошибка кода.
- NU1900 о недоступности nuget.org означает, что не получены данные аудита пакетов. Сообщать фактический результат сборки и существенные ограничения, не называть предупреждение успешным аудитом.
